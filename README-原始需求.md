## 二、核心 AI 能力

### 2.1 多模型 LLM 支持

| 特性 | 说明 |
|------|------|
| 多模型配置 | LLMConfig.Models[] 支持配置多个模型，每个模型独立 APIUrl / APIKey / Model |
| 模型选择 | 运行时通过 modelID 参数动态选择，UI 显示模型下拉选择器 |
| 向量配置 | 独立的 Embedding 配置（APIUrl、APIKey、Model、Dim） |
| MiniMax 兼容 | 系统消息自动转换为用户消息，适配不支持 system role 的模型 |
| Embedding 缓存 | 热点文本向量缓存，减少重复调用开销 |

### 2.2 Tool Calling 工具调用机制

| 特性 | 说明 |
|------|------|
| 循环调用 | 最多 5 轮工具调用，自动编排调用顺序 |
| 双路径策略 | Legacy 模式 + Tool Calling 模式并行，按模型能力自动降级 |
| 并行执行 | 同轮多个工具可并行调用，提升响应效率 |
| 简单问题加速 | ≤40字纯闲聊问题跳过 Agent 路径，直接快速响应 |
| 流式过滤 | StreamFilter 实时过滤工具调用噪音，平滑输出流 |

### 2.3 内置 AI 技能

| 技能 Key | 功能 | 说明 |
|---------|------|------|
| `search_knowledge` | 知识库检索 | 向量+关键词混合搜索，RRF 融合排序 |
| `search_logs` | 日志搜索 | KQL 语法支持，跨日志主题检索 |
| `search_alerts` | 告警搜索 | 告警事件多条件检索 |
| `get_alerts` | 活跃告警概览 | 当前触发中的告警摘要统计 |
| `get_n9e_alerts` | 夜莺告警 | Nightingale 告警检索（alerts/targets/full 三种范围） |
| `get_reports` | 巡检报告 | 最新 5 份巡检报告摘要 |
| `get_products` | 产品列表 | 活跃产品统计列表 |
| `get_assets` | 资产查询 | DB 实例 + CMDB 服务器（含产品维度过滤） |
| `get_slow_queries` | 慢查询分析 | 按产品统计慢查询趋势 |
| `lookup_ip` | IP 归属 | CMDB IP 归属查询（产品名称+备注） |
| `get_alert_rules` | 告警规则 | 告警规则配置查询 |
| `fetch_url` | URL 内容抓取 | 网页内容获取供 AI 分析 |
| `push_burst_alert` | 紧急告警推送 | 推送高危告警至突发响应平台 |
| `send_notification` | 钉钉通知 | 发送钉钉 Markdown 格式通知 |

> 所有技能可在系统管理 → AI 技能页面单独启用/禁用，MCP 工具动态叠加。

### 2.4 上下文引擎（Context Engine）

统一的 `ContextEngine` 负责在对话前构建结构化上下文，包含：

- **资产上下文**：CMDB 服务器列表、DB 实例（按产品分组）
- **IP 归属上下文**：自动识别问题中的 IPv4，拉取归属信息
- **产品维度上下文**：识别提到的产品线，关联慢查询/告警数据
- **记忆召回上下文**：从记忆空间检索相关历史记忆注入对话

## 三、记忆空间（Agent Memory）

### 3.1 记忆体系设计

```
用户对话 → 记忆提取器（MemoryExtractor）→ agent_memory 表
                │
                ▼
         记忆反射器（MemoryReflector）
                │  周期性整合/去重/升级
                ▼
         记忆召回器（MemoryRecall）
                │  相关记忆 → 注入对话上下文
                ▼
              LLM 回答（含历史记忆加持）
```

### 3.2 记忆维度

| 维度 | 说明 |
|------|------|
| 作用域（scope） | `private`（个人）/ `group`（用户组）/ `global`（全局） |
| Agent 范围 | `all` / `chatbot` / `assistant` / `workflow` |
| 记忆类型（type） | `fact`（事实）/ `insight`（洞察）/ `preference`（偏好）/ `episodic`（片段） |
| 分类（category） | 自由标注，支持多标签检索 |

### 3.3 记忆生命周期

| 阶段 | 组件 | 说明 |
|------|------|------|
| 提取 | MemoryExtractor | 对话结束后异步分析，识别值得记录的信息 |
| 存储 | AgentMemoryRepository | 持久化到 agent_memory 表 |
| 整合 | MemoryReflector | 定期合并重复/矛盾记忆，提炼高层洞察 |
| 召回 | MemoryRecall | 向量相似度 + 关键词匹配，返回 Top-K 相关记忆 |
| 导入/导出 | MemoryPortable | JSON 格式批量导入导出，支持迁移 |

### 3.4 前端管理

- **记忆空间**：个人/组/全局三视图，支持增删改查
- **记忆详情**：查看来源对话、事件流（创建/更新/提炼/召回）
- **召回测试**：输入文本实时测试记忆召回结果
- **用量分析**：记忆类型分布、召回频率统计

## 四、运维工单引擎（Ops Issue Engine）

### 4.1 工单流转

```
触发源（告警/巡检/手动）
        │
        ▼
   OpsRouter（路由分派）
        │
        ├── DiscoveryRule 匹配 → AI 自动分析
        │
        ▼
   OpsIssue（工单创建）
        │
        ├── OpsVerifier（结果核验）
        ├── OpsEscalation（升级策略）
        └── OpsNotifier（通知推送）
```

### 4.2 工单状态

| 状态 | 说明 |
|------|------|
| `open` | 新建待处理 |
| `in_progress` | 处理中 |
| `resolved` | 已解决 |
| `dismissed` | 已忽略 |
| `deleted` | 软删除（管理员操作） |

### 4.3 发现规则（DiscoveryRule）

| 属性 | 说明 |
|------|------|
| 触发条件 | 告警关键词/级别/来源等规则配置 |
| AI 分析模板 | 指定分析提示词模板 |
| 规则演化（RuleEvolver） | AI 根据历史处理经验自动优化规则 |
| 运行日志 | 每次触发记录 run_log（支持批量工单关联） |

### 4.4 效能报告（Efficiency Report）

- 工单处理时长分布
- 规则命中率统计
- 产品线故障趋势
- AI 自动解决率

## 六、知识库智能检索（RAG）

### 6.1 检索流程

```
用户问题
    │
    ▼
┌─────────────────┐
│  Vector Search  │──→ 向量相似度 Top-K
└────────┬────────┘
         │
┌────────▼────────┐
│ Keyword Search  │──→ BM25 关键词匹配
└────────┬────────┘
         │
    ┌────▼────┐
    │   RRF   │──→ Reciprocal Rank Fusion (k=60) 融合排序
    └────┬────┘
         │
    ┌────▼──────┐
    │ 过滤 < 0.4 │──→ 剔除低相关性结果
    └────┬──────┘
         │
         ▼
构建上下文 → LLM 回答（含 citations 引用溯源）
```

### 6.2 文档处理能力

| 能力 | 说明 |
|------|------|
| 自动分段 | 按 `##` 标题切分，段落间 3 句重叠保上下文连贯 |
| 自动摘要 | LLM 生成 summary + keywords，利于检索匹配 |
| 增量索引 | 文档创建/更新时异步触发向量索引重建 |
| 引用追溯 | 返回 doc_id、title、doc_type、score，支持答案溯源 |

### 6.3 向量存储

- **存储方式**：内存向量存储（in-memory）
- **相似度算法**：余弦相似度（Cosine Similarity）
- **产品过滤**：支持按产品维度隔离检索范围

## 十三、技术亮点总结

### 13.1 工具生态可插拔

- 内置技能覆盖告警、日志、知识库、资产、慢查询等核心场景
- **MCP 协议扩展**支持任意外部工具动态接入，支持用户组级别访问控制
- **SkillRegistry 统一注册中心**，AI 可感知全部可用工具

### 13.2 RAG 检索增强

- **向量 + 关键词双路检索**，兼顾语义理解与精确匹配
- **RRF 融合排序**（k=60）平衡两种检索方式的优势
- **引用溯源**返回文档来源，可查可纠

### 13.3 多模型兼容

- 支持配置多个 LLM 提供商，UI 支持运行时切换
- 自动适配各模型特性（如 MiniMax 的 system role 限制）
- **Embedding 缓存**减少热点文本重复向量化开销

### 13.4 主动智能

- **Cron 调度**定时执行 AI 任务
- **条件通知**机制（`[NOTIFY]` 标记）按需推送
- **运维工单引擎**将告警/巡检结果自动流转为可跟踪工单

### 13.5 长期记忆

- **Agent Memory** 系统跨对话持久化用户偏好、历史知识
- 记忆提取 → 反射整合 → 向量召回三阶段闭环
- 支持 private / group / global 三级作用域

### 13.6 可观测性

- **LLM 用量统计**全链路 Token 消耗追踪与费用估算
- **审计日志**覆盖 MCP 管理、工具调用、系统操作
- **工单效能报告**量化 AI 自动化运维价值

### 13.7 工具调用循环

- **最多 5 轮自动编排**，复杂问题可多次工具协同
- **Stream Filter** 实时过滤工具调用噪音，平滑输出流
- **简单问题自动识别**，跳过不必要的 Agent 路径
