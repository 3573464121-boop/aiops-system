# 智能运维诊断系统研究与实验协议

## 研究目标

本项目研究证据驱动的智能体方法能否提高运维故障诊断的准确性、可解释性与安全性。论文结论必须来自固定数据集、可复现实验配置和人工复核记录，不能只依据演示案例。

## 研究问题

- RQ1：相较于不调用工具的单轮大模型，工具调用智能体能否提高根因准确率并降低幻觉率？
- RQ2：相较于纯 BM25，BM25 与向量检索的 RRF 融合能否提高历史故障知识命中率？
- RQ3：加入长期记忆和资产关联后，证据召回率与根因准确率是否进一步提高？
- RQ4：人工审批与审计机制能否阻止未经授权的高风险处置，并形成完整责任链？

## 对照与消融配置

| 配置 | Agent 工具 | BM25 | 向量检索 | 记忆 | 资产关联 |
|---|---:|---:|---:|---:|---:|
| G0 单轮模型 | 否 | 否 | 否 | 否 | 否 |
| G1 工具基线 | 是 | 是 | 否 | 否 | 否 |
| G2 混合检索 | 是 | 是 | 是 | 否 | 否 |
| G3 加入记忆 | 是 | 是 | 是 | 是 | 否 |
| G4 完整系统 | 是 | 是 | 是 | 是 | 是 |

所有配置使用相同模型、提示词版本、案例顺序和超时设置。每次实验保存模型名称、数据源模式、知识检索模式、工具调用、证据来源和运行耗时。

## 数据纳入规则

诊断运行默认不属于论文数据集。只有满足以下条件的记录才能在“实验记录”页面标记为纳入：

1. 故障经过人工确认，具有明确的标准根因。
2. 告警与日志的时间窗口能够对应同一故障事件。
3. 删除令牌、账号、客户名称、外网地址等敏感信息。
4. 主机名、IP 和业务标识在导出前完成一致化匿名处理。
5. 数据集版本固定后不再根据实验结果修改标准答案。

建议正式实验至少收集 50 至 100 个真实或高保真故障案例，并由两名评审者独立标注部分样本。存在分歧时记录协商结果，并报告 Cohen's kappa 等一致性指标。

## 故障回放流程

1. 将单次故障的告警、日志、资产、诊断问题和人工确认的标准根因整理为一个 JSON 案例。
2. 完成敏感字段脱敏，固定 `version`，导入“故障回放”页面。示例见 `backend/eval/sample-fault-case.json`。
3. 对同一案例同时运行 `full`、`bm25` 和 `no-agent`。三组使用相同模型、问题与案例快照，只有 Agent 和检索配置不同。
4. 系统保存模型、配置、结构化诊断、证据、工具失败数、耗时和判官指标。回放使用隔离仓库，不写入日常诊断实验记录。
5. 同一模型同时充当被测模型和判官只用于开发阶段的相对比较，结果会标记为“自评”。正式实验应配置独立判官，并由至少两名人工标注者复核标准根因和判官结论。
6. 回放结果进入论文数据集前，管理员必须完成一次人工复核，填写是否采纳、根因是否正确和复核说明；人工复核结果与机器判官结果同时保留。

案例 JSON 和回放结果应与代码提交一同固定版本。记录模型版本、提示词版本、知识库快照、重复次数和随机参数；任何实验后修订都创建新案例版本，不覆盖原始案例。

## 评价指标

- 根因准确率：诊断是否识别出标准根因的核心故障机理。
- 证据召回率：标准答案要求的证据来源被系统实际引用的比例。
- 知识命中率：对应历史故障或知识文档是否被检索并引用。
- 忠实度：诊断结论中可由已引用证据支持的内容比例。
- 幻觉率：包含无证据支撑断言的案例比例。
- 平均诊断耗时：从请求开始到结构化结果完成的时间。
- 工具失败率：失败工具调用数占全部工具调用数的比例。
- 审批拦截率：高风险建议中被强制进入审批流程的比例。
- 审计完整率：关键操作中同时具有操作者、时间、对象和结果的比例。

## 统计方法

同一案例在不同配置下配对运行。二元结果优先使用 McNemar 检验，连续或有序指标根据分布使用配对 t 检验或 Wilcoxon 符号秩检验，并报告 95% 置信区间和效应量。模型存在随机性时，每个配置至少重复运行三次并报告均值与标准差。

## 有效性风险

- 当前判官与被测模型可能相同，存在自评偏差；正式实验应使用独立模型并抽样人工复核。
- 演示数据不能代表真实生产故障分布；主要结论应在脱敏真实数据上验证。
- 数据源版本和字段差异可能影响工具表现；实验报告需记录 Nightingale、日志平台和模型版本。
- 本系统当前不自动执行生产处置，安全性结论仅覆盖建议生成、权限控制、审批和审计闭环。

## 投稿前检查

- 固定并标记数据集版本、代码版本和实验配置。
- 完成全部消融实验及至少一次独立重复实验。
- 导出原始结果、聚合指标和失败案例分析。
- 检查数据授权、匿名化和伦理要求。
- 在论文中明确系统边界、负面结果和无法泛化的部分。
