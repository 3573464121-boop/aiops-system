# 回放结果人工复核清单

人工复核可以在功能开发和批量实验完成后集中进行，但必须在正式导出论文数据集和撰写实验结论前完成。

## 复核前

- 确认案例已经脱敏，不含账号、客户名称、公网地址、密钥和内部域名。
- 确认案例版本、标准根因、告警、日志和资产属于同一次故障事件。
- 确认本轮结果使用的被测模型、独立判官、知识库版本和实验配置已经固定。
- 失败或超时的运行不得替代有效结果；保留失败记录，并对相同配置重新运行。

## 每条结果

- 对照标准根因，判断诊断是否识别了核心故障机理。
- 检查诊断引用的证据是否真实存在，并且与结论直接相关。
- 检查是否出现证据未支持的具体断言、错误主机、错误依赖或错误时间关系。
- 检查高风险建议是否标记为需要审批。
- 检查系统质量告警；存在告警时在复核说明中明确解释。
- 选择“纳入”或“不纳入”，确认人工根因判断，并填写具体复核说明。

## 全部完成后

- 确认每个案例的 `full`、`bm25`、`no-agent` 均有有效结果。
- 确认论文统计只使用人工复核为“已采纳”的结果。
- 导出 JSON 作为完整实验档案，导出 CSV 用于统计分析。
- 随机抽取至少 20% 结果交给第二名评审者独立复核，并计算一致性指标。
- 保存未采纳结果和失败记录，在论文中说明排除规则与数量。
